# 09 · 项目作品集（转行的敲门砖）

> 转行求职，**作品集 > 简历文字 > 面试嘴皮子**。这 5 个项目从易到难，全部完成后你就有 3~4 个能上 GitHub、能现场演示的作品。

---

## 9.1 项目阶梯总览

| # | 项目 | 对应阶段 | 用时 | 亮点关键词 |
|---|---|---|---|---|
| P1 | 命令行工具助手 | 阶段 2 | 1 周 | Function Calling、工具闭环 |
| P2 | LangGraph 多步 Agent | 阶段 3 | 2 周 | 状态机、条件分支、记忆 |
| P3 | MCP 工具服务 | 阶段 4 | 1~2 周 | MCP 协议、工具工程化 |
| P4 | 个人知识库 RAG 问答 | 阶段 5 | 1~2 周 | RAG、pgvector、重排 |
| P5 | **毕业项目**：端到端 Agent 产品 | 阶段 6~7 | 3~4 周 | 全栈、流式、部署、评估 |

## 9.2 各项目验收标准

**P1 · 命令行工具助手**
- 终端里用自然语言让"助手"查文件、算数、查天气
- 演示"模型选工具 → 执行 → 回传 → 总结"的完整循环

**P2 · LangGraph 多步 Agent**
- 至少 2 个工具 + 条件分支 + 循环上限
- 带会话摘要记忆，多轮对话不爆上下文

**P3 · MCP 工具服务**
- 自建 MCP Server，能被 Claude/OpenClaw 实际调用
- 有工具 Schema 设计、错误处理、路径白名单

**P4 · 个人知识库 RAG 问答**
- 把你的网站文章/笔记入库，自然语言检索问答，回答附引用
- 加 Rerank/HyDE 前后质量对比（可量化）

**P5 · 毕业项目（重点做，做成代表作）**
- 选一个有真实价值的主题，例如：
  - **「折叠思维 · AI 研究助手」**：输入一个主题，自动搜索资料 → 生成结构化研究报告（深度研究 Agent + RAG）
  - **「个人知识库智能助手」**：聊天式访问你的全部笔记/文章，带引用和推荐
  - **「代码/运维助手」**：接入你的 Linux 服务器，自然语言执行安全运维操作（安全边界+人工确认）
- 要求：FastAPI + LangGraph + pgvector + Nuxt 前端 + SSE 流式 + Langfuse 追踪 + systemd/nginx 上线 + 评估集

## 9.3 GitHub 作品集包装（面试官第一眼看的）

每个项目仓库要有：
1. **README**：项目一句话简介 + 架构图 + 功能截图 + 快速启动命令
2. **清晰目录**：`app/` `evals/` `docs/` `deploy/` 分开
3. **架构图**：用 mermaid 画（你的网站/文档里已经习惯用）
4. **评估数据**：README 里放"优化前后准确率从 X% → Y%"
5. **一个能跑**：`docker compose up` 或 `uv run` 一键跑起来
6. **Commit 规范**：清晰的提交历史（说明你在持续迭代，不是一次性写完）

> 别小看 README 和截图——很多人代码不错但仓库像草稿，评分差很多。你做过开源网站，这块是加分项。

## 9.4 时间与精力分配建议

- P1~P4 是"熟练度练习"，做完就行，不用过度打磨。
- **把 60% 的精力砸在 P5 毕业项目**上，它决定面试时的谈资。
- 每个项目做的时候，把"为什么这么设计""踩了什么坑"写进 `docs/`，面试直接引用。
