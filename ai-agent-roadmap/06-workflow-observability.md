# 06 · 工作流编排 / 可观测性 / 评估

> 时长：2 周。Agent 能跑只是开始，**能稳定、可调试、可评估**才是生产级。这一章是工程师的看家本领，也是你和"纯 AI 爱好者"的分水岭。

---

## 6.1 工作流编排设计

- **状态机思维**：Agent 的执行本质是状态机——`思考 → 调工具 → 观察 → 决定下一步`。你懂图论和状态机，这里是降维打击。
- **控制流模式**：
  - 循环：最多迭代 N 次（防止 Agent 无限循环烧钱）
  - 分支：按条件走不同路径
  - 并行：`asyncio.gather` / LangGraph `Send` API 并发执行多个子任务
  - 超时与中断：单步超时、整体超时、人工中断
- **Human-in-the-loop**：关键节点（如"发送邮件""删除数据"）暂停等待人确认——安全且是加分项。

## 6.2 可观测性（Observability）

Agent 是黑盒，必须能看到它的"想法"和"动作"：

1. **结构化日志**：每个节点记录 `事件类型 + 输入 + 输出 + 耗时 + token 用量`。
2. **追踪（Tracing）**：完整还原一次任务的全链路（哪步调了哪个工具、哪个 LLM、耗时多少）。
   - 工具：LangSmith、Langfuse、Arize Phoenix、Helicone。
   - **推荐 Langfuse**（开源、可自部署，适合你的自托管习惯）。
3. **指标**：成功率、平均轮次、平均耗时、token 成本、工具调用失败率。
4. **异常处理**：LLM 返回格式错、工具超时、API 限流——都要有重试和降级策略（复用你后端的重试/熔断经验）。

## 6.3 评估（Evals）——Agent 开发最容易忽略、面试最爱问

**为什么需要**：Agent 是概率性的，改一个 prompt 可能这里变好那里变差，必须用评估集回归测试。

**评估体系**：
- **评估集（Eval Set）**：准备 20~50 个"黄金问答对"，覆盖常见场景 + 边界场景。
- **评估维度**：正确性、完整性、格式合规、工具调用是否正确、成本/耗时。
- **评估方式**：
  - 规则评估（代码判断，如 JSON 格式、关键词）
  - LLM-as-a-judge（让一个强模型给结果打分，判断"回答是否正确"）
  - 人工评估（抽样）
- **工具**：Langfuse / LangSmith 的 dataset + eval，或 RAGAS（专测 RAG）。

**实战建议**：每个 Agent 项目配一个 `evals/` 目录，`eval_set.jsonl` + 评估脚本，改代码就跑一遍看分数——这在简历上是非常亮眼的工程素养。

## 6.4 动手产出

- **P5-1**：给第 3 章的 Agent 接入 Langfuse，能可视化看到每一步的追踪。
- **P5-2**：写一个 20 条用例的评估集 + LLM-as-a-judge 评估脚本，对比"优化前后"的分数变化。
- **P5-3**：给 Agent 加循环上限、超时、降级策略，写清异常日志。
